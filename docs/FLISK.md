# Running wanderer with Flisk (optional)

`docker-compose.yml` stays the main way to run wanderer. This folder setup is an
optional extra for people who use [Flisk](https://flisk.sh), a local development tool.

## What is here

| Path | What it is |
| --- | --- |
| `services/wanderer/{search,db,web}/service.json` | One file per container, read from `docker-compose.yml` by `flisk import` |
| `.flisk/project.json` | Project name (`wanderer`) and the folders Flisk scans |
| `.autogenerated/docker-compose.yml` | A standalone Compose file generated from the `service.json` files. Do not edit it by hand |
| `.github/workflows/flisk-compose-check.yml` | Fails a PR when the generated file is out of date |

## Use it

Plain Docker Compose, no Flisk needed, same `.env` and same `./data` folder as `docker-compose.yml`:

```bash
docker compose --env-file .env -f .autogenerated/docker-compose.yml up -d
```

With Flisk (Tilt dashboard, logs per service, restart one service):

```bash
npx @flisk-sh/flisk up
```

## Change it

Edit a `service.json`, then regenerate the Compose file:

```bash
npx @flisk-sh/flisk-export compose . --force
```

## Differences from docker-compose.yml

- No `container_name`: containers are named `wanderer-search-1`, `wanderer-db-1`, `wanderer-web-1`. Services still reach each other by service name (`search`, `db`, `web`).
- The services use the default Compose network instead of the named `wanderer` network.
- `init: true` is set on every service.
- `env_file` is optional (`required: false`); the `${VAR:?}` checks still fail when a secret is missing from `.env`.
- Health check and port entries are written in long form (`["CMD", "sh", "-c", ...]`, `0.0.0.0:7700:7700`); they mean the same thing.

`flisk up` also writes local files (`.flisk/.flisk-out/`, `services/**/.autogenerated/`, `.tiltignore`, `shared-platform-engineering/`, a root `package.json`). All but the `package.json` are in `.gitignore`; do not commit the `package.json`.
